# DuckAI Chat Studio

رابط گفتگوی فارسی (RTL) با ظاهر تمیز، متصل به **Duck.ai**.
کل رابط، استاتیک است و روی **GitHub Pages** کار می‌کند؛ اتصال به Duck.ai از طریق یک واسط کوچک انجام می‌شود.

## ساختار

| فایل | کار |
|---|---|
| `index.html` | کل رابط کاربری در یک فایل (استاتیک، بدون بیلد) |
| `config.js` | تنظیم نشانی سرور واسط — بعد از دیپلوی همین را ویرایش کنید |
| `worker.js` | واسط آماده برای **Cloudflare Worker** (بدون پایتون) |
| `app.py` | همان واسط با پایتون، برای اجرای محلی |
| `404.html` | صفحهٔ خطای GitHub Pages |

## اجرا روی GitHub Pages

۱. مخزن را روی GitHub بسازید و این فایل‌ها را در شاخهٔ `main` بگذارید.
۲. **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `(root)`** و Save.
۳. سایت روی `https://<username>.github.io/<repo>/` بالا می‌آید.

همین. صفحه بدون هیچ سروری و بدون پایتون باز می‌شود. اما **GitHub Pages نمی‌تواند کد سرور اجرا کند**،
پس برای گفتگوی واقعی یک واسط لازم است (دلیلش پایین توضیح داده شده). رابط این را خودش تشخیص می‌دهد:
اگر واسطی پیدا نشود، تلاش می‌کند مستقیم به Duck.ai وصل شود و اگر مرورگر اجازه نداد، پیام روشن با دکمهٔ
«تنظیمات اتصال» نشان می‌دهد.

## راه‌اندازی واسط (یکی را انتخاب کنید)

**الف) Cloudflare Worker — بدون پایتون (پیشنهادی)**

1. در `dash.cloudflare.com` → Workers & Pages → Create → Worker
2. محتوای `worker.js` را جای‌گذاری و Deploy کنید
3. نشانی Worker را بردارید، مثل `https://duckai-relay.you.workers.dev`
4. آن را در `config.js` بگذارید:

```js
window.DUCKAI_CONFIG = { relay: "https://duckai-relay.you.workers.dev" };
```

یا بدون ویرایش کد، در خود سایت روی چرخ‌دندهٔ بالای صفحه بزنید و نشانی را وارد کنید (در مرورگر ذخیره می‌شود).

**ب) اجرای محلی با پایتون**

```bash
python3 app.py            # http://127.0.0.1:8000
python3 app.py --demo     # بدون اینترنت، برای دیدن ظاهر
```

هیچ پکیج اضافه‌ای لازم نیست (پایتون ۳.۹ به بالا).

## پروتکل اتصال به Duck.ai

1. **گرفتن توکن:** `GET https://duckduckgo.com/duckchat/v1/status` با هدر `x-vqd-accept: 1`
   → توکن در هدر پاسخ `x-vqd-4` برمی‌گردد.
2. **ارسال پیام:** `POST https://duckduckgo.com/duckchat/v1/chat`
   هدرها: `x-vqd-4: <token>` و `Content-Type: application/json`
   بدنه: `{"model": "<model id>", "messages": [{"role": "user", "content": "..."}]}`
   پاسخ: `text/event-stream` با خطوط `data: {"message": "..."}` و پایان `data: [DONE]`.
3. واسط همین جریان را به مرورگر پس می‌دهد و رابط متن را قطعه‌قطعه می‌نویسد.

**چرا مرورگر خودش نمی‌تواند؟** چون DuckDuckGo برای این endpoint هدرهای CORS نمی‌فرستد و خواندن
هدر `x-vqd-4` از مرورگر ممکن نیست. به همین دلیل یک واسط لازم است؛ اگر روزی DuckDuckGo اجازه بدهد،
رابط خودکار روی «اتصال مستقیم» می‌رود و به واسط نیازی نیست.

مدل‌ها: `gpt-4o-mini` (برچسب GPT-6 Luna)، `claude-3-haiku-20240307`، `meta-llama/Llama-3.3-70B-Instruct-Turbo`،
`mistralai/Mistral-Small-24B-Instruct-2501`، `o3-mini`. اگر شناسه‌ای عوض شد، `MODELS` را در `app.py`،
`worker.js` و `index.html` به‌روز کنید.

## امکانات رابط

- راست‌به‌چپ فارسی، فونت وزیرمتن، ریسپانسیو با کشوی کناری در موبایل
- حالت روشن و تاریک (ذخیره در مرورگر، پیش‌فرض بر اساس تنظیم سیستم)
- فهرست گفتگوهای اخیر با ذخیرهٔ محلی، عنوان خودکار، حذف گفتگو
- نمایش زندهٔ پاسخ با دکمهٔ توقف و دکمهٔ «دوباره»
- رندر مارک‌داون: سرتیتر، فهرست، جدول، نقل‌قول، بلوک کد با دکمهٔ کپی
- انتخاب مدل، پیشنهادهای آماده، `Enter` برای ارسال و `Shift+Enter` برای خط جدید

## نکته‌ها

- Duck.ai رابط رسمی و مستند ندارد؛ این پروژه یک کلاینت شخصی برای آن است. تغییر پروتکل یا
  محدودیت نرخ (HTTP 429) ممکن است رخ دهد — خطا در همان صفحه نمایش داده می‌شود.
- خطای HTTP 418 یعنی Duck.ai چالش ضدربات خواسته است؛ در آن حالت هدرهای مرورگر باید به‌روز شوند.
- تاریخچهٔ گفتگو فقط در `localStorage` مرورگر شما ذخیره می‌شود و جایی فرستاده نمی‌شود.
